## 2. Пакет и `pyproject.toml`

**Пакет** — папка с модулями Python, которую ставят в окружение и потом импортируют откуда угодно: `from urec.io import read_jsonl`. Наш пакет лежит в `src/urec/` (так называемый src-layout, блок 20).

`pyproject.toml` — паспорт пакета:

| Раздел | Что задаёт |
|---|---|
| `[build-system]` | чем собирать пакет — setuptools |
| `[project]` | имя `urec`, версию, Python от 3.11 и зависимости |
| `[project.optional-dependencies]` | набор `dev`: pytest, hypothesis, mypy, pre-commit |
| `[tool.setuptools.packages.find]` | где искать код — в `src/` |
| `[tool.ruff]` | длина строки 100; папки `external` (форк) и `notebooks` ruff не проверяет |
| `[tool.pytest.ini_options]` | тесты лежат в `tests/`; метки `gpu` (нужна видеокарта) и `network` (нужен интернет) |
| `[tool.mypy]` | строгая проверка типов (раздел 9) |

- **Установка в режиме разработки** — `pip install -e ".[dev]"` в папке репозитория. `-e` (editable) ставит в окружение не копию кода, а ссылку на `src/urec`: правка в коде видна сразу, без переустановки. `.[dev]` — пакет из текущей папки (`.`) плюс набор `dev`.
- **Зависимости добавляются вместе с кодом**, которому они нужны. Сейчас их три: `orjson` и `zstandard` для `urec.io`, `huggingface-hub` для `urec.data.tofu`.
- **Точных версий в `pyproject.toml` нет** — они закреплены в `envs/` (раздел 11).

## 3. Контракты: `urec/types.py`

Контракты данных — договорённость о формате файлов между частями программы (разбор E, раздел 9). В коде каждый контракт — **dataclass**: класс, в котором перечислены поля с типами, а `@dataclass` сам пишет конструктор, сравнение и печать:

```python
@dataclass
class ItemResult:
    run: str
    success: bool
    q_star: int | None          # int или None
    ...
    schema_version: int = 1     # значение по умолчанию
```

`ItemResult(run="…", success=True, …)` создаёт объект, `a == b` сравнивает все поля, `print(a)` печатает их.

Классы — ровно по блоку 22, у каждого поля комментарий о его смысле:

| Класс | Что описывает | Где хранится |
|---|---|---|
| `QAItem` | вопрос TOFU: `item_id`, вопрос, эталонный ответ, ключевые факты, `evaluable` | `data/items/{split}.jsonl` |
| `Node` | один запрос атаки и ответ на него, оценка R, успех | строка `nodes.jsonl.zst` |
| `ItemResult` | итог атаки по одному вопросу | строка `items.csv` |
| `HardExample` | трудный диалог для обучения TAU | строка `tau/round{k}/hard.jsonl` |
| `RunSpec` | описание одного запуска | `results/raw/{run}/spec.yaml` |
| `Manifest` и `StepStatus` | что и как запущено, состояние каждого шага | `results/raw/{run}/manifest.json` |

`QAItem` заполняет `urec.data.tofu` (раздел 5); остальные классы заполнят модули следующих вех.

Три правила классы проверяют сами в `__post_init__` — методе, который dataclass вызывает сразу после создания объекта:

- `QAItem` превращает списки `perturbed_answers` и `keys` в кортежи (`tuple`). В JSON кортежей нет: после чтения файла там списки, и без этого прочитанный объект не был бы равен записанному.
- `HardExample` проверяет правило блока 22: ответов на один меньше, чем вопросов (ответы `y_1 … y_(t-1)` к вопросам `q_1 … q_t`). Иначе — ошибка с понятным текстом.
- `Manifest` превращает состояния шагов, прочитанные из JSON как словари, в объекты `StepStatus`.

**`schema_version`** есть у каждого класса из блока 22, сейчас она равна 1 и записывается в каждую строку файла. Если формат класса когда-нибудь изменится, версию поднимут до 2 — и чтение старого файла сразу остановится с сообщением, а не разложит данные не по тем полям.

**`Record`** в начале файла описывает для проверки типов «любую запись из этого файла» — любой класс с полем `schema_version`. Благодаря ему mypy знает, что `read_jsonl(path, QAItem)` возвращает список `QAItem`.

## 4. Запись и чтение: `urec/io.py`

Файлы-интерфейсы в основном в формате **JSONL**: одна запись JSON на строку. Такой файл можно дописывать по строке и читать по строке, не загружая целиком. JSON пишет библиотека `orjson`: она быстрее стандартной и пишет буквы не-ASCII как есть (`Жюль Верн`, а не `\u0416\u044e…`).

| Функция | Что делает |
|---|---|
| `atomic_write(path, data)` | пишет байты во временный файл `path.tmp` рядом и переименовывает его в `path` |
| `write_jsonl(path, records)` | записывает небольшой файл `.jsonl` целиком, атомарно |
| `read_jsonl(path, cls)` | читает файл `.jsonl` в список объектов класса `cls` |
| `JsonlZstWriter(path)` | потоковая запись большого сжатого журнала `.jsonl.zst` |
| `read_jsonl_zst(path, cls)` | чтение такого журнала по одной записи |
| `mark_done(folder)`, `is_done(folder)` | маркер `DONE`: шаг, писавший в папку, выполнен |
| `sha256_file(path)` | отпечаток файла — для lock-файлов и данных в `manifest.json` |

**Зачем атомарная запись.** Colab может отключиться посреди записи. Если писать прямо в итоговый файл, останется обрубок, похожий на готовый файл, и следующий шаг молча прочитает неполные данные. Поэтому файл сначала пишется под временным именем, а потом одним действием `os.replace` переименовывается: под итоговым именем лежит либо старый файл, либо новый целиком. Маркер `DONE` ставится последним — папка с ним точно дописана. На этом будет держаться пропуск выполненных шагов при повторном запуске (разбор E, раздел 8).

**Большие журналы.** Атака записывает тысячи узлов `Node` — это десятки мегабайт текста, поэтому журнал сжимается форматом zstd (`.zst`) прямо во время записи:

```python
with JsonlZstWriter(path) as writer:     # пока пишем, файл называется path.part
    for node in nodes:
        writer.write(node)
# вышли из with без ошибок — файл переименован в path
```

- Пока запись идёт, файл называется `….part`, и каждые 100 записей сжатые данные сбрасываются на диск.
- Если внутри `with` случилась ошибка, итогового файла не будет, а записанное до ошибки останется в `.part` для разбора.
- `read_jsonl_zst` — генератор: отдаёт записи по одной (`for node in read_jsonl_zst(path, Node): …`), поэтому даже большой журнал не загружается в память целиком.

**Проверки при чтении.** Каждая строка проверяется: это объект JSON, `schema_version` та же, что в коде, а поля — ровно поля класса. Ошибка называет файл и номер строки, например:

```
ValueError: data/items/forget01.jsonl:7: schema_version 2, а код знает QAItem версии 1
```

## 5. Данные TOFU: `urec/data/tofu.py`

TOFU (разбор C; план, блок 13) — 200 вымышленных авторов по 20 пар «вопрос — ответ», пары одного автора идут подряд. Модуль превращает сплиты TOFU в списки `QAItem`.

| Функция | Что делает |
|---|---|
| `read_tofu(name)` | скачивает файл сплита и возвращает его строки — словари `{"question": …, "answer": …}` |
| `load_split(name)` | сплит как список `QAItem`; для forget-сплитов подтягивает `{name}_perturbed` |
| `make_items(name, rows, perturbed)` | превращает строки в `QAItem` — это `load_split` делает после скачивания |
| `match_perturbed(rows, perturbed)` | находит для каждой строки сплита её строку в `_perturbed` |
| `extract_author(items)` | имя автора по его 20 парам (раздел 6) |
| `build_retain_eval(n=400, seed=0)` | фиксированный набор retain для оценки (раздел 7) |
| `build_retain_pool(retain_eval)` | пул retain для вехи M5 (раздел 7) |

**Как скачиваются данные.** Каждый сплит TOFU на Hugging Face — один файл JSON Lines: `forget01.json`, `forget01_perturbed.json`, `retain95.json` и так далее. `read_tofu` скачивает нужный файл через `huggingface_hub` один раз, дальше он берётся из кэша Hugging Face на диске.

- **Версия закреплена:** `TOFU_REVISION = "324592d…"` — версия (коммит) датасета от 27 марта 2025 года, последняя на сегодня. Если авторы TOFU что-то поменяют, у нас данные останутся прежними — так же, как версии моделей закреплены в `envs/models.lock.json`.
- **Почему не `datasets.load_dataset`, как в плане.** Библиотеки `datasets` в окружении `atk` нет, а её свежие версии требуют `fsspec` не новее 2026.6.0 (в `atk` стоит 2026.9.0). Без понижения `fsspec` установщик находит только `datasets` 1.1.1 2020 года, а понижать — значит менять `atk`. Ради чтения нескольких файлов JSON это лишнее: `huggingface_hub` в `atk` уже есть. Строки идут в том же порядке, в каком их видит OpenUnlearning: у каждого сплита ровно один файл.

**Что лежит в `QAItem`** (поля — раздел 3):

- `item_id` — сплит и номер строки из четырёх цифр: `forget05/0137`. Номер берётся из исходного сплита и больше никогда не меняется: по нему склеиваются все файлы проекта.
- `author_local = index // 20` — номер автора внутри сплита (`//` — деление нацело).
- `paraphrased_answer` и `perturbed_answers` (5 неверных ответов) есть только у forget-сплитов, они берутся из `{name}_perturbed`. У остальных сплитов там `None` и пустой кортеж.
- `keys` пока пуст, `evaluable` пока `True`: ключевые факты и настоящая проверка появятся в вехе M2 (план, блок 25).

**Сопоставление с `_perturbed`.** План предупреждает: порядок строк в `forget05` и `forget05_perturbed` не обязан совпадать. Поэтому пары ищутся по тексту вопроса, и любая неувязка — ошибка с понятным текстом:

- вопрос повторяется в одном из файлов;
- для вопроса нет пары или в `_perturbed` лишние строки;
- у найденной пары другой ответ.

Сейчас порядок строк в TOFU совпадает, но код от этого не зависит — это проверяет тест, который перемешивает строки `_perturbed`.

## 6. Имя автора: `extract_author`

Имя автора понадобится в вехах M3 и M6: в сценариях B1 и B3 первый ход — вопрос-контекст об авторе. Поэтому имя должно быть верным у всех 200 авторов.

В плане для M0 предложен запасной способ — «самая частая пара слов с заглавной буквы» (основной, через spaCy, требует тяжёлую модель). Проверка на всех 200 авторах TOFU показала, что пара слов ошибается:

- имя из трёх слов превращается в пару: «Basil Mahfouz» вместо «Basil Mahfouz Al-Kuwaiti»;
- строчная частица рвёт имя: у «Isabella van Pletzen» побеждает город «Cape Town»;
- у одного автора (номер 88 из 200) имени в данных нет вовсе, его везде называют «the author»; пара слов выдаёт жанр «Urban Fiction»;
- притяжательная форма `Williams'` прятала последнее слово: получалось «Xin Lee» вместо «Xin Lee Williams».

Поэтому правило уточнено:

1. Вопрос и ответ делятся на слова. Цепочка «слов имени» — подряд идущие слова с заглавной буквы; внутри цепочки могут стоять частицы `van`, `der`, `de`, `von` и прозвище в скобках, как в «Alejandro (Alex) Fuentes».
2. Знак препинания и притяжательная форма (`Al-Kuwaiti's`, `Williams'`) обрывают цепочку.
3. Из цепочек берутся все куски длиной 2–4 слова, которые начинаются и кончаются словом с заглавной буквы.
4. Для каждого куска считается, в скольких парах из 20 он встречается. Побеждает самый частый; при равенстве — более длинный, то есть полное имя, а не его часть.
5. Если победитель встречается меньше чем в половине пар, имени в данных нет, и `author = None` (в `QAItem` поле так и описано: `str | None`).

Результат проверен глазами на всех 200 авторах: 199 имён верные и целые (ни одно не обрезано и не прихватило соседнего слова), у автора 88 — `None`. У 191 автора имя есть во всех 20 парах, у остальных — не меньше чем в 17. spaCy для этого не нужен: правило верно на всём TOFU, а версия данных закреплена.

## 7. Наборы retain: `retain_eval` и `retain_pool`

Оба набора строятся из `retain95` — сплита, который идёт в паре с `forget05`:

- **`retain_eval`** (в плане D_r^eval) — 400 вопросов retain для оценки. Это случайная выборка с сидом 0: тот же сид — тот же набор, это проверяет тест. Файл запишет кусок 3, и дальше он не меняется (блок 25).
- **`retain_pool`** — пул кандидатов для retain-режимов вехи M5 (блок 30): `retain95` без `retain_perturbed` и без `retain_eval`.

Сколько пар: в `retain95` 3800, из них 400 — пары `retain_perturbed` (первые 20 авторов). Остаётся 3400 кандидатов: 400 уходят в `retain_eval`, 3000 — в пул.

- **Почему без `retain_perturbed`.** Эти 400 пар использует оценка TOFU в OpenUnlearning: на них считаются метрики retain, из которых складывается Model Utility (конфиг `TOFU_QA_retain_eval` в форке). Наши наборы с ними не пересекаются.
- **Подводный камень.** Вопрос «What is the full name of the author?» в TOFU есть у двух авторов: у Aurelio Beltrán (он в `retain_perturbed`) и у Isabel Martínez (её там нет). Поэтому пары сравниваются по вопросу вместе с ответом: по одному вопросу из пула ошибочно выпала бы пара Isabel Martínez.
- Выбранные пары идут по порядку строк, `item_id` у них из `retain95`: например, `retain95/0412`.

## 8. Тесты

**Тест** — функция, которая проверяет код на заранее известном примере. Тесты запускает программа **pytest**: находит в `tests/` файлы `test_*.py`, выполняет в них функции `test_*` и печатает, какие прошли. Внутри теста `assert условие` — проверка: если условие ложно, тест упал.

| Файл | Что проверяет |
|---|---|
| `tests/unit/sample_records.py` | это не тест, а образцы: по одной записи каждого класса, тексты из forget01 |
| `tests/unit/test_types.py` | у всех классов версия 1; списки становятся кортежами; правило `HardExample`; словари шагов становятся `StepStatus` |
| `tests/unit/test_io.py` | записал → прочитал → тот же объект — для каждого класса, в `.jsonl` и в `.jsonl.zst`; файл правда сжат; сброс на диск работает; оборванная запись не оставляет итогового файла; чужая версия, строка без нужных полей, оборванная строка и список вместо объекта — ошибки с местом в файле; буквы не-ASCII пишутся как есть; атомарная запись, маркер `DONE`, sha256 |
| `tests/fixtures/tofu_mini.jsonl` | это не тест, а данные: первые 20 строк `forget01_perturbed`, все пары автора Basil Mahfouz Al-Kuwaiti. Лицензия TOFU — MIT, поэтому копию можно хранить в репозитории |
| `tests/unit/test_tofu.py` | без интернета, на фикстуре: поля `QAItem`; сопоставление с `_perturbed`, даже когда строки перемешаны; ошибки, когда строки не хватает или ответ другой; пары идут блоками по 20; имя из трёх слов; порог «хотя бы половина пар»; частица `van`, прозвище в скобках, `Williams'` |
| `tests/integration/test_tofu_real.py` | на настоящем TOFU, нужен интернет: размеры 40/200/400/3800; у forget-сплитов есть все ответы из `_perturbed`; 12 имён, проверенных глазами; без имени только автор 88; каждое имя встречается хотя бы в половине пар автора; тот же сид даёт тот же `retain_eval`; в наборах retain нет пар `retain_perturbed`, и друг с другом они не пересекаются |

Приёмы pytest в этих тестах:

- `tmp_path` — pytest даёт тесту новую пустую временную папку, тест пишет файлы туда;
- `@pytest.mark.parametrize("record", ALL_RECORDS, …)` — один тест для каждой записи из списка; в выводе это `test_jsonl_round_trip[QAItem]`, `test_jsonl_round_trip[Node]` и так далее;
- `with pytest.raises(ValueError, match="…")` — тест проходит, только если внутри возникла ошибка `ValueError` с таким текстом;
- `pytestmark = pytest.mark.network` в начале файла ставит метку `network` всем тестам файла;
- `@pytest.fixture(scope="module")` — функция готовит данные один раз на весь файл (например, загружает сплиты), а тесты получают их как аргумент с тем же именем: `def test_split_sizes(splits, …)`.

Всего 51 тест: 39 без интернета и 12 с ним. Они идут несколько секунд; в первый раз дольше, пока скачиваются файлы TOFU.

**Ловят ли тесты ошибки.** Код нарочно ломали и смотрели, упадут ли нужные тесты:

- `urec.io` и `urec.types` — 8 поломок: итоговое имя файла при ошибке, приведение к кортежам, превращение шагов в `StepStatus`, проверка версии, сброс на диск, правило `HardExample`, понятная ошибка на оборванной строке, проверка, что строка — объект JSON;
- `urec.data.tofu` — 13 поломок, по одному правилу за раз: частицы, прозвище, `'s`, кавычки в конце слова, выбор более длинного имени, порог «половина пар», поиск пары по вопросу, проверка ответа, сравнение retain по вопросу вместе с ответом, исключение `retain_perturbed`, порядок строк, сид, блоки по 20.

Каждый раз падали нужные тесты.

## 9. Проверка типов: mypy

Подсказки типов (`item_id: str`, `-> list[T]`) Python при выполнении не проверяет. Это делает **mypy**: он читает код и находит, например, место, где функции, ждущей `str`, передают `None`. `strict = true` в `pyproject.toml` — самый строгий режим: у всех функций должны быть подсказки типов (правило блока 21 для слоёв 0–3). Сейчас mypy проверяет `types.py`, `io.py` и папку `data`; с каждым куском список растёт.

Одно исключение в настройках: `untyped_calls_exclude = ["zstandard"]`. В описании типов библиотеки zstandard у метода `close()` нет подсказок, и строгий режим запрещал бы его вызывать. Исключение касается только zstandard.

## 10. Проверка на GitHub (CI)

**CI** (continuous integration) — программа на серверах GitHub. При каждом Pull Request она берёт чистую машину с Linux, ставит всё с нуля и прогоняет проверки. Так видно, что код работает не только «у меня». Описание — в `.github/workflows/ci.yml`:

| Строка | Что делает |
|---|---|
| `on:` — `pull_request` и `push` в `main` | когда запускаться: при каждом PR и после каждого слияния в `main` |
| `actions/checkout@v7`, `submodules: recursive` | скачать репозиторий вместе с форком; если коммита форка нет на GitHub (забыли `git push` в форке), CI упадёт уже здесь |
| `actions/setup-python@v7`, `python-version: "3.11"` | поставить Python 3.11, как в окружениях `unl` и `atk` |
| `pip install -r envs/requirements-cpu.txt && pip install -e ".[dev]"` | пакеты точных версий, затем сам `urec` |
| `pre-commit run --all-files --show-diff-on-failure` | те же автопроверки, что при коммите (разбор E, раздел 5), но на всех файлах; при ошибке показывает, что исправить |
| `mypy src/urec/types.py src/urec/io.py src/urec/data` | проверка типов |
| `pytest -m "not gpu" -q` | все тесты, кроме помеченных `gpu`; тесты `network` идут: у машин GitHub есть интернет |

**Где смотреть.** На странице PR внизу — блок проверок. Зелёная галочка и «All checks have passed» — всё прошло. Красный крестик — нажать Details: откроется журнал, и в нём видно, какой шаг упал и почему. Все запуски собраны во вкладке Actions репозитория. PR вливается только с зелёной галочкой.

- Форк и этот репозиторий открыты, поэтому CI скачивает их без токенов. По той же причине в форке не должно быть ничего секретного.
- TOFU тоже открыт: строка `You are sending unauthenticated requests to the HF Hub` в журнале — не ошибка, токен не нужен.
- В журнале CI первого куска было предупреждение pre-commit: `pre-commit-hooks` v4.6.0 из плана использует устаревшие названия стадий, которые уберут в будущих версиях pre-commit. Во втором куске версия поднята до v6.0.0 — проверки те же, предупреждения нет.

## 11. Пакеты для тестов: `envs/requirements-cpu.in` и `.txt`

Для CI нужно маленькое окружение без GPU (блок 9). Его описывают два файла:

- `requirements-cpu.in` пишется руками — это список того, что нужно (`orjson`, `pytest`, …);
- `requirements-cpu.txt` пишет программа `uv pip compile` (команда — в начале обоих файлов). В нём точные версии всех пакетов, включая зависимости зависимостей, и откуда каждый взялся (`# via`).

Флаг `-c envs/requirements-atk.lock` велит взять для общих с `atk` пакетов те же версии, что в `atk`. Так тесты на GitHub идут на тех же версиях, на которых код будет работать в Colab. Новый пакет — новая строка в `.in` и та же команда заново. Во втором куске так добавлен `huggingface-hub`, его версия — 1.10.2, как в `atk`.

## 12. Чем код отличается от плана

| В плане | У нас | Почему |
|---|---|---|
| в `pyproject.toml` сразу 7 зависимостей | пока 3, остальные — вместе с кодом | видно, зачем нужна каждая; CI не ставит лишнего |
| `ruff` в наборе `dev`; CI запускает `ruff check . && ruff format --check .` | CI запускает `pre-commit run --all-files`, а ruff ставит сам pre-commit | в `atk` стоит ruff 0.16.9, в автопроверках — 0.6.9, как у OpenUnlearning. Разные версии по-разному оформляют код, и CI падал бы на оформлении. Так на GitHub та же версия, что при коммите |
| CI при каждом push | при каждом PR и push в `main` | иначе в PR одна и та же проверка шла бы дважды |
| CI ставит torch для CPU | пока нет | ни одному тесту он пока не нужен; добавим, когда понадобится |
| в `urec.io` только функции для `.jsonl.zst` | ещё `write_jsonl` и `read_jsonl` | `data/items/*.jsonl` и `hard.jsonl` — обычный JSONL без сжатия |
| у `StepStatus` названы только поля | типы полей наши: время — строка вида `2026-10-14T12:30:05`, `status` — строка | блок 22 их не задаёт |
| `schema_version` у всех классов | у шести классов блока 22; у `StepStatus` своей нет | `StepStatus` не пишется отдельно — он часть `Manifest`, и версия у `Manifest` |
| `pre-commit-hooks` v4.6.0 | v6.0.0 | с v4.6.0 pre-commit предупреждает, что её названия стадий устарели (раздел 10) |
| TOFU читается через `datasets.load_dataset` | файлы TOFU скачиваются через `huggingface_hub` по закреплённой версии | `datasets` в `atk` не ставится без изменения окружения (раздел 5) |
| из `{name}_perturbed` подтягивается и `paraphrased_question` | не хранится | в `QAItem` (блок 22) нет такого поля, и дальше в плане оно не используется |
| `extract_author`: самая частая сущность PERSON из spaCy, запасной способ — самая частая пара слов | уточнённое правило из раздела 6; возвращает `str \| None` | пара слов ошибается на реальных именах; у автора 88 имени нет |
| тест «во всех 20 ответах каждого автора встречается имя» | 12 имён, проверенных глазами; без имени только автор 88; имя — хотя бы в половине пар автора | полное имя стоит во всех 20 ответах лишь у 109 авторов из 200: в ответах часто «she», «he» или одно имя без фамилии |

## 13. Как запустить проверки у себя (по желанию)

Нужен Python 3.11 для Windows. В папке репозитория:

```bash
pip install -r envs/requirements-cpu.txt
pip install -e ".[dev]"
pytest
mypy src/urec/types.py src/urec/io.py src/urec/data
pre-commit run --all-files
```

Без интернета тесты с меткой `network` упадут; их можно пропустить: `pytest -m "not network"`. Без всего этого то же самое проверит CI на GitHub.

## 15. Частые ошибки

| Что видно | Причина | Что делать |
|---|---|---|
| `ModuleNotFoundError: No module named 'urec'` | пакет не установлен в окружение | `pip install -e .` в папке репозитория |
| `schema_version 2, а код знает … версии 1` | файл записан другой версией кода | взять файл, записанный этой версией кода, или записать его заново |
| `запись не подходит к QAItem: … missing … argument` | в строке файла нет нужного поля или есть лишнее | файл испорчен или от другой версии; сообщение называет файл и строку |
| ошибка соединения или `LocalEntryNotFoundError` в тестах `network` | нет интернета или Hugging Face недоступен | `pytest -m "not network"`; тесты с сетью прогонит CI |
| `UserWarning: … cache-system uses symlinks …` на Windows | Windows не даёт создавать символические ссылки без режима разработчика | безвредно: кэш Hugging Face работает, только занимает чуть больше места |
| CI красный на шаге `pre-commit` | автопроверка нашла ошибку или поправила оформление | в журнале CI видно, что именно; исправить у себя, закоммитить и отправить |
| CI красный на шаге `actions/checkout`, в журнале `not our ref` | в репозитории коммит форка, которого нет на GitHub | `git push` в форке (разбор E, раздел 3) |
